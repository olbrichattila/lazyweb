Feature overview

What the reviewed source describes

Lazy Coding Agent is a Free Pascal/Lazarus desktop coding workspace. This page summarizes reviewed README, help and source; it does not claim release availability, a live runtime check or user testing.

Status distinction: “Implemented in reviewed source/docs” describes evidence in the application repository. It does not mean shipped, release-ready or verified in a running application. The README's active-integration status needs owner confirmation.
Reviewed source/docs

Workspace and editor

Documentation describes project navigation, a single-file editor, Markdown preview, chat and optional guidelines, utility and terminal panels. Panels can be shown, hidden and detached; the layout is described as persistent per workspace.

Reviewed source/docs

Ask, Plan and Agent

Ask provides read/search-oriented tools; Plan can save plan Markdown; Agent can use patch, write and shell tools. By default, write paths and shell working directories stay within the workspace. A per-session option allows outside-workspace changes.

This is application-level path handling, not an operating-system sandbox. Shell and write actions run on the user's machine. Use Agent mode only when you trust the workspace and model.

Reviewed source/docs

Sessions and execution detail

Reviewed source/help describe multiple sessions with separate engines, saved conversation history, tool-error records and an execution detail view for recorded context and tool inputs/outputs.

The trace is not a guaranteed replay or an exposure of private hidden chain-of-thought.

Documented examples

Providers, models and images

The README names examples including Claude 3.7 Sonnet, Hermes 4 70B/405B, GPT-4o and DeepSeek R1; exact model IDs and routing depend on configuration. Help describes PNG, JPEG, WebP and GIF image attachments, up to four per message and 5 MiB each, with possible downscaling.

Model availability, capability, provider behavior and costs depend on configuration and third parties. Image understanding needs a vision-capable model.

Caveats apply

Integrated terminal

Reviewed documentation describes a PTY terminal opened at the workspace root. Windows requires Windows 10 1809 or newer for ConPTY; Linux builds require PTY/libutil support and the documented terminal dependencies.

These are documented requirements, not a promise of identical runtime behavior on every platform.

Rules and preferences

README/help describe dark and light themes, per-workspace Markdown project rules injected into prompts, and debugging/Learn behavior settings. No broader plugin or extensibility claim is made.

Project rules and settings topics →

Planned work is separate

Multi-agent collaboration, execution-plan tracking, workspace knowledge/RAG and The Brain are described as future features with no backend. SQLite/vector retrieval is future planning, not a current feature. See the roadmap.

Platform build configuration

The repository has build workflow configuration for Linux, Windows and macOS. CI configuration is not proof of a recent successful build or runtime parity. See the release and developer-build status for the distinction.
