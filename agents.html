Agent architecture

A single agent loop, per session

Reviewed application sources describe one agent engine for each chat session, running the model/tool loop asynchronously so the interface can remain responsive.

Evidence and maturity: This architecture description comes from reviewed source and help, not a live application run or release test. The app records observable context and tool activity; that is not private hidden chain-of-thought.

From prompt to result

Prepare session context

The session engine builds or refreshes its system prompt with the selected mode, workspace, permitted tools and project rules, then adds the user's message and any supported image attachments.

Request a model response

The configured LLM receives conversation context and the tool definitions available in the selected mode. Context summarization may be used when configured.

Run permitted tools

If the model returns tool calls, the application runs the corresponding local tools and records results, including error results. The tool boundary applies workspace path policy.

Continue or stop

The loop continues until a final response, cancellation, an error or the configured step limit. Activity and execution detail show application-recorded steps and tool I/O.

What execution detail shows

The application help describes Tools & Logs and Execution Detail for prompts/context, model responses and tool arguments/results represented by the app. The visible trace explains application activity; it does not reveal hidden reasoning and does not promise exact replay or a sanitized export.

Mode boundaries

Ask exposes read-oriented tools. Plan can save plan files but does not expose arbitrary writes or shell. Agent enables mutations and shell. By default, writes and shell working directories are constrained to the workspace; a per-session option permits outside-workspace modifications. This is application-level policy, not an OS-level sandbox.

Future multi-agent ideas

Specialist-agent collaboration, execution-plan tracking, workspace knowledge/RAG and The Brain are marked as future features with no backend in the reviewed help. They are not shown here as an operational workflow. See planned work.
